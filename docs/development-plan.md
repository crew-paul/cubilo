# 큐빌로 (Cubilo) — 최종 개발 계획서

> **문서 버전:** v1.5 (사용자 현재 Mac 필수 지원 환경 추가)  
> **작성일:** 2026-11-15  
> **상태:** 제품 범위 확정 / 기술 PoC 진행 전 / 일정은 PoC 후 확정  
> **개발 방식:** macOS에서 개발, Windows 10·11 및 macOS용 네이티브 앱 공동 개발  
> **한 줄 목표:** 초등학교 3~6학년이 도형을 선택하고 속성을 켜고 끄는 것만으로 키링, 연필꽂이, 수납함 등 실제 출력할 수 있는 3D 작품을 만드는 무료·오프라인·저사양 친화적 모델링 앱.

---

## 0. 이번 개정에서 확정한 사항

1. **기본 UX는 `도형 선택 → 속성 토글 → 필요한 수치 조절 → 즉시 미리보기`로 고정한다.** 별도 Shell/Bevel/Modifier 편집 화면을 MVP에 만들지 않는다.
2. 상자·원기둥에 **속 비우기(Hollow)**, **모서리 둥글게(Rounded)**, **위쪽 좁히기/넓히기(Taper)** 등 해당 도형에 적합한 속성을 제공한다.
3. 속성을 끄더라도 이전 입력값은 보존한다. 사용자 편집 데이터는 비파괴적으로 유지한다.
4. **도형의 속성**과 **여러 도형을 조합하는 Boolean/그룹 기능**을 구분한다. 그룹은 부품 묶음이며, 합치기는 실제 형상 연산이다.
5. 원통형·사각형 **속 빈 통은 MVP에서 직접 제작 가능**해야 한다. 범용 곡면 Shell은 후속 기능이다.
6. **키캡 전용 생성기**와 **조립 모드**는 제품 로드맵에 포함하되 MVP 출시 조건에서는 제외한다. 기본 도형·치수 기능으로 단순 키캡 형상을 실험하는 것은 가능하다.
7. **Windows 10 x64는 필수 정식 지원**이다. Windows 11 x64 및 macOS Apple Silicon도 지원한다. **RAM 4GB + Intel HD Graphics 500 및 520**에서 각각 실기기 검증한다.
8. **Rust + egui/eframe + wgpu**를 유지한다. geometry 및 renderer를 독립 모듈로 설계한다.
9. STL을 생성하여 **Bambu Studio**에서 슬라이싱하는 흐름을 사용한다. 프린터 직접 제어는 하지 않는다.
10. 일정은 **1인 풀타임 약 5~8개월**을 기준으로 하되, GPU/Boolean/한글 텍스트 선행 검증에서 재산정한다.

## 1. 제품 요구사항(PRD)

### 1.1 목적과 사용자

| 구분 | 정의 |
|---|---|
| 주 사용자 | 초등학교 3~6학년 |
| 보조 사용자 | 교사, 학부모, 3D 프린팅 입문자 |
| 주요 장소 | 학교 컴퓨터실, 가정, 방과후 교실 |
| 제품 | 무료 설치형 3D 모델링 프로그램 |
| 핵심 가치 | 별도 CAD 지식 없이 도형을 조작하고, 속성으로 형태를 바꿀 수 있음 |
| 출력 경로 | 프로젝트 저장 → STL 내보내기 → Bambu Studio |
| 연결 정책 | 로그인·서버 통신 없이 기본 기능 전부 사용 가능 |

### 1.2 대표 사용자 시나리오

**A. 속이 빈 연필꽂이**

1. 원기둥을 추가한다.
2. 크기를 `지름 60mm × 높이 80mm`처럼 조절한다.
3. 우측 패널의 **속 비우기**를 켠다.
4. 벽 두께 `2mm`, 바닥 두께 `3mm`, 윗면 열림을 설정한다.
5. 미리보기를 확인하고 STL로 내보낸다.
6. Bambu Studio에서 내부가 비어 있는 형상으로 슬라이싱되는지 확인한다.

> 위 치수는 **기능 설명용 예시**다. 실제 출력 가능 두께는 소재·노즐·슬라이서 설정에 따라 달라진다.

**B. 한글 이름 키링**

1. 상자를 추가하고 **모서리 둥글게**를 켠다.
2. 3D 텍스트를 추가해 한글 이름을 입력한다.
3. 글자를 받침에 양의 깊이로 겹쳐 배치하고 **합치기(Boolean Union)**를 실행한다. 단순히 면끼리 접하게 두지 않는다.
4. 구멍 도형이 결합된 받침을 관통하도록 배치해 **빼기(Boolean Difference)**를 실행한다.
5. 글자의 분리된 자모·획이 받침을 통해 연결되는지 검사한다.
6. 저장 후 STL을 내보내고 슬라이싱으로 결합·구멍을 확인한다.

**C. 작은 수납함**

1. 상자를 만들고 **속 비우기**를 켠다.
2. 너비·깊이·높이 및 벽·바닥 두께를 바꾼다.
3. 필요하면 별도 상자 도형으로 뚜껑을 만든다. 정밀 끼워맞춤 도구는 후속 버전에서 지원한다.

**D. 키캡(후속 버전)**

1. 키캡 템플릿을 선택한다.
2. 프로파일, 크기, 둥글기, 내부 공간, 호환 스템을 선택한다.
3. 글자·무늬를 추가한다.
4. 시험 출력으로 맞춤 정도를 검증한다. **키캡 결합 규격 및 공차는 실제 스위치와 프린터에 맞춰 검증한다.**

**E. 조립형 장난감(후속 버전)**

1. 여러 부품을 독립된 모델로 구성한다.
2. 부품을 정렬하고 간섭 여부를 확인한다.
3. 필요하면 파트를 나누고 별도 STL로 내보낸다.
4. 조립 모드는 비작동 장난감·교육용 모형·생활 소품을 대상으로 한다.

### 1.3 제품 설계 원칙

- **쉽게 발견:** 초등학생이 기능을 이름과 그림만 보고 이해할 수 있어야 한다.
- **적은 화면 이동:** 주요 동작을 하나의 화면에서 완료한다.
- **점진적 노출:** 토글이 꺼져 있을 때는 세부 값을 숨긴다.
- **비파괴 편집:** 속성과 원본 도형 값을 나중에 다시 수정할 수 있어야 한다.
- **출력 가능한 결과:** 시각적 모양과 실제 STL 메시가 일치해야 한다.
- **저사양 우선:** 화면 렌더링과 기하 계산을 독립시켜 UI가 멈추지 않도록 한다.
- **완전 오프라인:** 설치 후 모델링·저장·출력 작업에 인터넷이 필요하지 않다.

### 2.2 속성 패널 규칙

1. 선택한 도형에 **적용 가능한 토글만** 노출한다.
2. 토글을 켜면 기본값으로 형태를 즉시 바꾸고 관련 입력 필드를 펼친다.
3. 토글을 끄면 형상 적용만 중지하고 마지막 설정값은 남긴다.
4. 수치 변경은 슬라이더와 직접 입력을 함께 지원한다. 직접 입력값은 mm 단위로 표시한다.
5. 속성 조합이 불가능하면 해당 조합을 **비활성화하고 이유를 안내**한다. 잘못된 메시를 생성하지 않는다.
6. 연속 슬라이더 조작은 Undo 기록 한 건으로 묶는다.
7. 메시 생성이 오래 걸리면 마지막 유효 미리보기를 유지하고 최신 변경만 처리한다.
8. 선택이 해제되면 속성 패널은 빈 상태 안내를 표시한다.
9. 기능 라벨은 어린이 친화적 표현을 사용한다. 예: `속 비우기`, `모서리 둥글게`, `위쪽 좁히기`.
10. 속성 토글은 도형별 형상 파라미터이며, 여러 객체 간의 **합치기/빼기**는 별도 상단 도구로 유지한다.

| 구 | MVP | — | — | 후속 | 부분 자르기(후속) |
| 원뿔 | MVP | 후속 | 후속 | 기본 구조에서 상·하단 지름 조절 | 평평한 윗면 |
| 토러스 | MVP | — | — | — | 링 굵기 |

### 2.4 `속 비우기`의 동작 정의

- 대상: MVP에서는 **상자·원기둥**.
- 기본값: `활성화=false`; 활성화하면 `윗면 열기=true`.
- 편집값: **벽 두께, 바닥 두께, 윗면 열림 여부**.
- 최소 치수보다 벽·바닥이 두꺼운 경우는 적용을 막고 친절한 오류를 안내한다.
- 외부 크기를 유지한 채 내부 공동(cavity)을 생성한다.
- 윗면 열림 상태에서는 내부 공간이 외부와 연결되어야 한다.
- STL 내보내기 결과에는 시각적인 구멍이 아니라 **실제 내부 면과 바닥·벽이 있는 유효 메시**가 포함되어야 한다.
- 윗면을 닫으면 천장 두께는 바닥 두께와 같은 값을 사용한다. 닫힌 상태는 `높이 > 바닥 두께 × 2`를 만족해야 한다. UI에는 `바닥·천장 두께`로 표시한다.
- 원기둥 Hollow + Taper의 벽 두께는 경사 측면에 수직인 두께로 정의한다. 내부 단면은 외부 측면의 평행 오프셋으로 계산하고, 내부 공간 전체가 유효한 경우에만 허용한다. PoC에서 구현·검증하지 못하면 이 조합은 비활성화한다.
- 크기 변경으로 기존 두께·반경이 불가능해지면 변경 전체를 거절하고 이전 유효 상태와 값을 유지한다. 자동으로 값을 줄이지 않는다. OFF 상태의 보존값은 유지하며, 재활성화 시 다시 검사한다.
- 지원 불가능한 토글 조합은 UI에서 제한한다. 억지로 모두 조합하지 않는다.

### 2.5 `둥글게` / `좁히기`의 동작 정의

- **둥글게:** MVP 상자는 수직 모서리 네 곳을 둥글게 한 2D 단면을 높이 방향으로 돌출한다. 위·아래 테두리의 3D Fillet은 MVP에서 제외한다. Hollow 결합 시 외부 반경은 `r`, 내부 반경은 `max(r - 벽 두께, 0)`으로 정의하고 외부 치수를 유지한다. 유효한 내부 단면을 만들 수 없으면 조합을 거절한다. 원기둥 가장자리 둥글기는 PoC에서 단면·두께 규칙을 검증한 옵션만 제공하며, 검증하지 못한 옵션은 MVP에서 제외한다.
- 상자 등의 기본 형상을 만들 때 반경을 파라미터로 적용한다. Boolean 결과의 임의 모서리를 자동 탐지해 Fillet하는 기능과 다르다.
- **좁히기/넓히기:** 원기둥의 상단 지름을 조절하는 Taper부터 구현한다. 향후 사각 상자에도 추가한다.
- **화면 스무딩:** 법선 보간은 조명만 부드럽게 표현한다. 실제 출력 형상이 부드러워지려면 정점 형상도 달라져야 한다.
- 반경·두께 등의 입력 허용 범위는 도형 크기에 따라 동적으로 제한한다.

## 3. 지원 플랫폼 및 최소 사양

### 3.1 정식 지원 정책

| 플랫폼 | 범위 | 상태 |
|---|---|---|
| **Windows 10 x64** | **22H2 기준, 정식 지원 필수** | 필수 |
| **Windows 11 x64** | 정식 지원 필수 | 필수 |
| **macOS Apple Silicon** | 정식 지원 | 필수 |
| macOS Intel | 호환 빌드 및 실기기 테스트 후 지원 여부 공표 | 조건부 |
| Linux | 공통 코드 이식성 고려, 배포 후순위 | 제외 |

- Windows 10은 **실행 가능성만이 아닌 모델링·저장·STL·성능까지 정식 검증 대상**이다.
- Windows 10 32비트는 초기 범위에서 제외한다.
- Windows 10의 일반 지원은 2025-10-14 종료되었다. **앱 호환성 지원과 운영체제 보안 업데이트는 별개**임을 릴리스 안내에 명시한다.
- Windows 10 LTSC 및 이전 기능 업데이트에 대한 보장은 별도 테스트 전에는 하지 않는다.

| 현재 디스플레이 설정 | 논리 해상도 2560×1440, 60Hz; 시스템 보고 렌더링 픽셀 5120×2880 |

- 이 장비에서 Rosetta가 필요 없는 **arm64 네이티브 앱**으로 실행되어야 한다. macOS 최소 배포 버전은 15.2 이하로 설정하고, 이후 의존성 갱신이 이 환경을 제외하지 않도록 관리한다. 더 이전 macOS 지원 범위는 별도 검증 후 공표한다.
- 필수 기능은 설치·실행, 카메라·선택·변환, 속성 토글, 한글 입력·텍스트, Boolean, Undo/Redo, 저장·복구, STL 생성 및 오프라인 사용이다.
- 공통 1280×720 시험과 현재 디스플레이 설정에서의 일반 창·최대화 시험을 구분한다. HiDPI 배율에 따른 뷰포트 크기, 클릭 좌표, 글자·Gizmo 표시와 렌더링 부하를 검증한다.
- 성능은 §7의 고정 프로젝트·합격선을 적용하고 창 크기·렌더링 픽셀 크기·배율을 함께 기록한다. 필요한 경우 3D 뷰포트 렌더링 해상도 배율을 조정할 수 있으나 UI 가독성과 선택 정확성을 유지해야 한다.
- 현재는 하드웨어 정보만 확인한 상태이며 앱 실행·성능 검증 완료를 의미하지 않는다. 이 장비에서 필수 검증이 실패하면 릴리스 조건을 충족하지 못한다.

### 3.2 최소 하드웨어 목표

| 항목 | 목표 사양 |
|---|---|
| RAM | **4GB** |
| GPU | **Intel HD Graphics 500 및 Intel HD Graphics 520** 두 계열 검증 |
| 해상도 | **1280×720** 이상 |
| CPU | 별도 최소 모델 확정 전. 실제 GPU 탑재 기기에서 CPU도 함께 측정 |
| 저장 공간 | 설치 파일/프로젝트 크기 측정 후 확정 |
| 인터넷 | 불필요 |
| 3D 프린터 | 앱에는 필요하지 않음. STL을 별도 Bambu Studio에서 출력 |

**주의:** HD 500과 HD 520은 동일한 그래픽 칩이 아니다. GPU API 지원 목록만으로 실행 가능성과 실제 FPS를 판단할 수 없다. **실기기·실제 드라이버**로 검사한다.

- Windows: **설치 프로그램 + 포터블 ZIP**.
- macOS: `.app` 패키지, 필요 시 DMG 배포. 공용 배포 시 코드 서명·공증 검토.

- 학교 보안 정책상 포터블 EXE도 차단될 수 있으므로 설치 권한 필요 여부를 안내한다.

## 5. 기술 스택과 시스템 아키텍처

### 5.1 기술 스택

| 계층 | 기술 | 비고 |
|---|---|---|
| 개발 언어 | **Rust** | 공통 네이티브 코드 |
| UI/앱 창 | **egui + eframe** | macOS·Windows 공통 UI |
| 3D 렌더링 | **wgpu** | `egui-wgpu` 커스텀 렌더링 연동 |
| 수학 | **glam** | Transform·Ray·행렬 |
| Boolean | **Manifold 계열** | `manifold-rust` 우선 평가, `manifold-csg` 비교 |
| 파라메트릭 형상 | **직접 작성하는 shape generator** | 도형별 토글·치수 기반 메시 생성 |
| 파일 직렬화 | **serde** | 포맷 버전 관리 |
| 백그라운드 처리 | Rust 스레드/채널 | 최신 작업 우선, UI 비차단 |
| 빌드·테스트 | GitHub Actions | Windows/macOS 네이티브 러너 |

- `eframe`, `egui-wgpu`, `wgpu`는 **공존 가능한 버전**을 PoC에서 확인하고 잠근다. 서로 다른 최신 버전을 무작정 설치하지 않는다.
- `Cargo.lock`을 소스 관리에 포함한다.
- `manifold-rust`의 기능 제공 여부만으로 품질을 확정하지 않고 실제 부하에서 벤치마크한다.
- `egui-wgpu`의 Paint Callback은 UI 안의 3D 작업 공간을 구현하는 첫 후보이다.

**의존성 규칙**

- `studio-core`와 `studio-geometry`는 **UI/GPU/운영체제에 의존하지 않는다**.
- `studio-app`은 사용자 입력을 **Command**로 변환한다.
- `studio-render`는 평가된 메시·씬 변화 정보만 받는다.
- `studio-io`는 **원본 도형·토글 파라미터**를 저장한다. 캐시된 GPU 버퍼는 저장하지 않는다.
- 필요한 OS별 기능(파일 경로·설치·창)은 앱/플랫폼 어댑터에 한정한다.

### 5.3 내부 데이터 구조 설계(개념 예시)

```rust
struct ToggleProperty<T> {
    enabled: bool,
    params: T, // OFF 상태에서도 마지막 설정값 보존
}

struct HollowParams {
    wall_thickness_mm: f32,
    bottom_thickness_mm: f32,
    open_top: bool,
}

struct RoundedParams {
    radius_mm: f32,
}

struct TaperParams {
    top_diameter_mm: f32,
}

struct CylinderProperties {
    diameter_mm: f32,
    height_mm: f32,
    hollow: ToggleProperty<HollowParams>,
    rounded: ToggleProperty<RoundedParams>,
    taper: ToggleProperty<TaperParams>,
}

enum Primitive {
    Box(BoxProperties),
    Cylinder(CylinderProperties),
    Sphere(SphereProperties),
    Cone(ConeProperties),
    Torus(TorusProperties),
    Hemisphere(HemisphereProperties),
    Text(TextProperties),
}

enum NodeKind {
    Primitive(Primitive),
    Boolean { operation: BooleanOp, children: Vec<NodeId> },
    Group { children: Vec<NodeId> },
}

struct SceneNode {
    id: NodeId,
    transform: Transform,
    kind: NodeKind,
}
```

> 위 Rust 코드는 **설계 개념**으로 타입/직렬화/참조 방식은 실제 구현에서 정리한다. `NodeId`는 별도 노드 저장소와 연결하고, 순환 참조를 금지한다. `Group`과 `Boolean`의 변환 좌표계·자식 소유권도 명확히 정의한다.

### 5.4 메시 생성 파이프라인

```text
사용자: 원기둥 선택 + '속 비우기' ON + 벽 두께 변경
    ↓
Command 적용 / Scene 버전 증가 / Undo 기록
    ↓
파라미터 검사 및 정규화 (크기·두께·속성 조합)
    ↓
Shape Generator (바깥 형상 + 내부 공동 + 열린 윗면)
    ↓
기본 도형 메시 완성 / 유효성 검사
    ↓
Boolean Node 평가 (있을 때만)
    ↓
최신 결과 캐싱 ┬──→ wgpu 뷰포트 갱신
                └──→ STL Export용 평가 메시
```

- 한 도형의 속성만 바뀌면 변경된 노드 및 영향을 받는 상위 CSG 노드만 다시 평가한다.
- **도형의 로컬 속성 처리 순서**를 정의하고, 동일 입력에 동일한 메시가 나오도록 한다.
- 여러 토글을 무작정 직렬로 메시 후처리하지 않는다. 가능한 경우 도형의 단면/프로파일을 통합해 직접 생성한다.
- 토글 조합별 **지원 매트릭스 + 기하 정합성 테스트**를 반드시 구축한다.
- 무거운 CSG 및 메시 계산은 작업 스레드에서 수행한다.
- 계산 결과에 Scene Revision을 포함해 **오래된 결과가 최신 씬을 덮어쓰지 못하게** 한다.
- 메시 캐시와 GPU 버퍼는 재생성 가능한 자료로 보고 메모리 예산을 둔다.

### 5.5 3D 뷰포트와 입력

- 카메라 회전·팬·줌은 egui 입력 이벤트와 3D 카메라를 분리해 처리.
- **선택(Picking)은 CPU Ray Casting부터**, 필요하면 BVH 도입.
- 이동·회전·크기 핸들(Gizmo)은 어린이가 쉽게 집을 수 있는 클릭 영역 확보.
- 이동·회전은 Transform만 변경하고 원본 메시를 재생성하지 않는다.
- 기본 도형의 크기 변경은 로컬 치수 파라미터를 수정해 메시를 재생성한다. 벽·바닥 두께와 둥글기 반경의 mm 값은 유지한다.
- MVP에서 그룹·Boolean 결과 전체의 크기 핸들은 제공하지 않는다. 이동·회전 및 자식 도형의 치수 편집을 지원한다. 일반 비균일 Scale은 MVP에서 제외하며, Transform의 Scale은 1로 유지한다.
- 화면 업데이트는 **변경 발생 시 렌더링**을 우선하고, 드래그 중에는 필요한 FPS 유지.
- 그림자·고가 셰이더는 MVP에서 기본 비활성화.

### 5.6 GPU 백엔드 전략

1. Mac: Metal로 개발·테스트.
2. Windows: **DX12 / Vulkan 중 동작 가능한 백엔드**를 우선 테스트.
3. 실패 시 동일 wgpu의 **GL 백엔드**도 검증하되, GL은 제한적인 지원 경로라는 점을 고려한다.
4. `eframe`의 `Glow` 모드로 UI를 바꾸는 것만으로 **wgpu 3D 뷰포트가 자동 대체되지 않는다**. 완전한 별도 3D 렌더러는 PoC 결과가 요구할 때만 검토한다.
5. 실행 시 GPU·드라이버·백엔드 정보를 기록하고, 오류 발생 시 사용자가 이해할 수 있는 안내 표시.
6. **Windows 10 HD 500과 HD 520에서 모두 실측 통과할 때** 최소 사양으로 공표한다.

### 5.7 Geometry / Boolean 선택 기준

- 비교 후보: 순수 Rust `manifold-rust`, C++ 기반 바인딩 `manifold-csg`.
- 샘플: 사각 통 내부 빼기, 원통형 통, 키링 구멍, 서로 접하는 형상, 얇은 벽, 다중 Boolean.
- 측정: 연산 성공률, 결과 메시 폐합성, 유효한 법선/면 방향, 처리 시간, 피크 메모리, 취소 가능성, Windows/macOS 빌드 난이도.
- **MVP 결정을 위한 필수 조건**은 기능 목록보다 실제 유효 STL 생성과 저사양 안정성이다.

### 5.8 3D 텍스트

- 한글과 영문의 폰트 윤곽선을 읽어 2D 경계/내부 홀 처리 후 삼각형 분할, 두께 방향 돌출 메시 생성.
- 글자 내부 구멍(예: `ㅇ`, `ㅁ`)이 정상 유지되는지 검사한다.
- 배포 가능한 한글 폰트를 포함하고 해당 라이선스 명시.
- Phase 0에서 한글 조합 입력, 조합 중 단축키 억제, 윤곽선·홀 처리, 돌출, 받침과의 합치기 및 STL을 검증한다. 분리된 자모·획이 받침을 통해 연결되는 사례를 포함한다.
- 사용자 폰트는 후속 기능으로 분리할 수 있다.

## 6. 저장, 출력, 형상 검사

### 6.1 프로젝트 포맷

- 자체 포맷(가칭 `.k3d`)으로 **편집 원본** 저장.
- 포함: `schemaVersion`, 도형 종류, 크기·속성 활성화 상태·입력값, 노드 관계, Transform, 색상, 단위, 프로젝트 메타데이터.
- 제외: 재생성 가능한 GPU 버퍼, 임시 렌더링 상태.
- 저장은 **임시 파일 → 완료 검증 → 원자적 교체**를 우선하여 파일 손상 위험을 줄인다.
- 자동 복구는 원본 프로젝트와 분리된 로컬 파일로 유지한다.
- 향후 포맷 변경에 대비한 마이그레이션 테스트를 작성한다.

### 6.2 STL 내보내기

1. 내보내기를 누른 시점의 씬 스냅샷과 Revision을 고정하고, 해당 상태를 출력 해상도로 최종 평가한다. 평가 중 이후 편집은 내보내기 대상에 반영하지 않는다.
   - 해당 스냅샷의 평가·메시 검사가 성공한 경우에만 파일을 생성한다. 실패·취소 시 이전 캐시 메시를 대신 내보내지 않는다.
   - 화면에는 계산 대기·계산 중·최신 결과·실패를 구분한다. 마지막 유효 미리보기가 현재 입력과 다르면 이를 표시한다.
   - 미리보기와 출력 메시의 차이는 삼각형 근사 오차로 제한한다. 물리 치수·속성·연결 관계는 동일해야 하며, 출력 품질별 허용 오차를 PoC에서 기록한다.
2. 객체/노드 Transform을 반영하고 **mm 좌표계**로 내보내기.
3. 열린 경계, 퇴화 삼각형, 뒤집힌 면, 비정상 체적 등 검사.
4. 복수의 독립된 물체는 선택된 내보내기 정책에 따라 하나의 STL(복수 셸) 또는 개별 파일로 처리. 부품별 일괄 내보내기 UI는 후속 로드맵.
5. 출력 불가능하거나 위험한 형상에는 경고 및 수정 가이드 제공. 자동 복구를 보장하지 않는다.
6. **Bambu Studio**에서 STL 로드 후 모형이 비어 있는지, 벽·바닥·구멍이 올바르게 슬라이싱되는지 확인.

> STL은 단위·색상·조립 관계를 명시적으로 보존하지 못한다. MVP는 **mm 기준 단색 형상 출력**으로 정의한다.

### 6.3 출력 전 사용자 안내

- 너무 얇은 벽, 바닥 없는 통, 뚫리지 않은 구멍, 공중에 뜬 독립 부품 등을 검사 가능한 범위에서 경고.
- 프린터·소재에 따른 최소 두께와 부품 맞춤 오차는 달라진다. 고정된 하나의 숫자를 모든 출력물의 정답처럼 제시하지 않는다.
- `출력 준비 완료`는 **검사를 통과했다는 의미**이며, 실제 출력 성공을 보증하지 않는다고 명시.

## 7. 성능·호환성 기준

### 7.1 기준 시험 환경

- **Windows 10 22H2 x64**, RAM 4GB, Intel HD Graphics 500 / HD Graphics 520 **각각 별도 테스트**.
- Windows 11 x64 및 macOS Apple Silicon도 기본 기능 회귀 테스트. 사용자 현재 Mac mini M1 / 8GB / macOS 15.2는 §3.1.1에 따라 성능·HiDPI·전체 필수 기능을 실기기로 검증한다.
- 해상도 **1280 × 720**.
- 벤치마크 프로젝트: 빈 씬, 도형 100개, 500개, 속 빈 원기둥, 속 빈 상자, 단순 CSG, 3D 한글 텍스트.
- 각 프로젝트는 도형별 분할 수·총 삼각형 수·CSG 깊이·텍스트 및 폰트·난수 시드를 고정해 저장한다. 동일 카메라 경로, 선택·이동·회전·속성 변경 절차로 측정한다. 유휴 시와 조작 시를 분리한다.
- 500개 씬의 잠정 합격선은 30초 조작 중 입력→화면 반영 지연 p95 100ms 이하, UI 무응답 1초 이상 0회로 정한다. 측정 방식과 지원 장비 CPU·드라이버를 Phase 0에서 고정하고 변경 시 근거를 기록한다.
- 메모리는 유휴뿐 아니라 Boolean·Undo·캐시·내보내기가 겹치는 시나리오의 프로세스 피크를 측정한다. 캐시·Undo 예산과 작업 제한은 RAM 4GB 실기기 결과를 기준으로 Phase 0에서 확정한다.
- 보고 항목: 평균 FPS, p95 프레임 시간, 앱 메모리, GPU 백엔드, GPU/드라이버, 실패율, 저장·내보내기 시간.

### 7.2 MVP 잠정 합격선

| 항목 | 필수 합격선 | 최적화 목표 |
|---|---|---|
| 앱 유휴 메모리 | **250MB 이하** | 150MB 이하 |
| 단순 도형 100개 조작 | **평균 30FPS 이상** | 평균 60FPS |
| 단순 도형 500개 | **고정 조작 30초, 입력 지연 p95 ≤100ms, 1초 이상 UI 무응답 0회** | 평균 30FPS 이상 |
| 일반 이동·회전 조작 | 끊김 없이 사용 가능 | 입력 응답 50ms 이내 |
| 속성 토글 | UI가 멈추지 않고 최종 결과 표시 | 작은 도형은 즉각적 갱신 |
| Boolean 처리 | UI 메인 스레드 블로킹 없음 | 단순 작업 0.5초 이내 지향 |
| 저장/복원 | 손실 없이 재편집 가능 | 일반 프로젝트 1초 이내 저장 지향 |
| 오프라인 | **핵심 기능 100% 사용 가능** | 동일 |
| Windows 10 | **설치·실행·편집·STL 검증 성공** | 동일 |

> 수치는 아직 측정하지 않은 **개발 목표**이며, 합격선을 만족하지 못한다면 해당 최소 사양을 공식 지원한다고 주장하지 않는다. 부하 시나리오 및 측정 방법을 동일하게 유지한다.

### 7.3 저사양 최적화 정책

- 반복 도형 메시 공유와 GPU 인스턴싱을 우선 검토한다.
- 편집 중 Transform만 바뀌면 메시 재생성을 하지 않는다.
- 속성이 바뀐 형상만 갱신하고 CSG는 의존 노드 단위로 재평가한다.
- 오래된 결과 폐기와 실행 중 연산 취소를 구분한다. PoC에서 후보 엔진의 실제 취소 지원 여부를 기록한다.
- 기본 무거운 형상 작업은 동시에 1개만 실행하고, 대기 요청은 노드별 최신 요청으로 병합한다. 실행 중 작업을 취소할 수 없으면 완료 결과를 Revision으로 폐기한다.
- 취소 불가능한 연산에 대비해 입력 삼각형 수·CSG 깊이·텍스트 길이 제한을 PoC 실측으로 정하고 초과 요청은 실행 전에 안내한다. 내보내기는 고정 스냅샷을 사용하는 별도 요청으로 보존하고 UI에 대기 상태를 표시한다.
- 메시 분할 수는 기본값을 보수적으로 정하고, 내보내기 메시와 미리보기 메시의 해상도를 분리할 수 있다.
- 오래된 캐시 제거, 리소스 해제, 대용량 파일/메시 복잡도 제한으로 RAM 사용량을 통제한다.

## 10. 테스트 계획

### 10.1 핵심 형상 회귀 테스트

| 테스트 ID | 입력/조작 | 기대 결과 |

| G-01 | 원기둥 Hollow ON | 윗면 열린 공동, 유효한 벽과 바닥 |
| G-02 | 원기둥 Hollow OFF → ON | 이전 벽/바닥 두께 값 복구 |
| G-03 | 상자 Hollow + 치수 수정 | 외부 크기 유지, 내부 공간 업데이트 |
| G-04 | 벽 두께가 반지름보다 큼 | 적용 차단·안내, 데이터 손상 없음 |
| G-05 | 원기둥 Hollow + Taper | 허용한 조합에서 유효 메시, 미지원 시 안내 |
| G-06 | Rounded 반경을 최대치 초과 | 입력 제한 또는 오류 안내 |
| G-07 | 속성 슬라이더 연속 드래그 | Undo 한 번으로 드래그 시작 전 상태 복원 |
| G-08 | 속 빈 통 + 구멍 도형 빼기 | 새로운 결과가 폐합된 유효 메시 |
| G-09 | 그룹화 / 합치기 | 그룹은 원본 유지, 합치기는 평가 메시 반영 |
| G-10 | 한글 3D 텍스트 | 글자 안쪽 구멍과 돌출 형상 유지 |
| G-11 | 프로젝트 저장→재열기 | 모든 토글 활성 상태와 비활성 설정값 유지 |
| G-12 | STL 저장→슬라이싱 | 내부 공동·바닥·구멍 정상 표시 |
| G-13 | Hollow 도형 크기 변경 | 외부 치수 변경, 두께 mm 유지; 불가능한 변경은 원상 유지 |
| G-14 | 계산 중 내보내기 후 추가 편집 | 클릭 시점 스냅샷 출력; 평가 실패 시 이전 메시 출력 금지 |
| G-15 | 닫힌 Hollow 및 Rounded 결합 | 천장·바닥 두께 동일, 정의된 내부 반경·유효 단면 유지 |
| G-16 | 한글 글자·받침 결합 | 분리된 자모·획도 받침과 연결되고 관통 구멍 유지 |
| G-17 | 취소 불가 연산 중 연속 편집·삭제·Undo | 작업 수 제한 준수, 오래된 결과 미적용, 최종 상태 평가 |
| G-18 | 한글 조합 입력 중 단축키 | 조합 문자 유지, 삭제·도형 명령 오작동 없음 |

### 10.2 플랫폼 테스트

- [ ] Windows 10 22H2 x64 + HD 500 + RAM 4GB.
- [ ] Windows 10 22H2 x64 + HD 520 + RAM 4GB.
- [ ] Windows 11 x64 일반 PC.
- [ ] macOS Apple Silicon: 사용자 현재 Mac mini M1 / 8GB / macOS 15.2 필수 실기기, arm64 네이티브·현재 디스플레이·HiDPI·성능 포함.
- [ ] macOS Intel 지원 여부 확인용 빌드/테스트(조건부).
- [ ] 모든 필수 플랫폼에서 네트워크 차단 상태의 사용 검증.
- [ ] Windows 설치형·포터블 실행 검증.

### 10.3 어린이 사용성 테스트

대상: 초등학교 3~6학년. 다양한 학년을 포함하여 소규모 반복 테스트를 수행한다.

**과제 예시**

1. 원기둥을 추가해 60mm 크기로 만든다.
2. **속 비우기**를 찾아 연필꽂이로 만든다.
3. 벽 두께를 변경한다.
4. 상자를 추가하고 모서리를 둥글게 만든다.
5. 프로젝트를 저장하고 STL을 내보낸다.

측정: 과제 완료 여부, 도움이 필요했던 횟수, 기능을 찾기까지 걸린 시간, 오류·포기 지점. 목표치는 첫 파일럿 결과를 기반으로 현실적으로 확정한다.

## 11. CI/CD 및 개발 운영

```text
Mac 로컬 개발 / macOS Metal 실행
                 │
                 ▼
        GitHub Push / PR
                 │
         GitHub Actions
           ├─ macOS 빌드 + 테스트
           └─ Windows x64 빌드 + 테스트
                 │
                 ▼
       실제 Windows 10/11 기기
       ├─ GPU 호환성
       ├─ FPS / 메모리 / 입력
       └─ STL / 오프라인 / 설치
                 │
                 ▼
           릴리스 후보 승인
```

- Windows의 CI는 **빌드와 CPU 로직 테스트**를 보장한다. 가상 CI의 그래픽 환경은 HD 500/520 실기기 테스트를 대신하지 못한다.
- 테스트 데이터는 장비·드라이버·백엔드·앱 커밋 ID를 포함해 저장한다.
- 기능 병합 전에 Rust 코드 검사 및 크로스플랫폼 테스트 통과.
- 외부 의존성·폰트·아이콘의 라이선스 확인.
- 오류 로그는 기본적으로 로컬에만 기록하고 외부 자동 전송하지 않는다.

## 14. 개발 착수 순서 및 우선순위

**가장 먼저 구현할 세 가지**

1. **공통 3D 뷰포트 + Win10 저사양 GPU 실행 확인**.
2. **원기둥 `속 비우기` 토글 + 벽/바닥 두께 → STL 생성**.
3. **비파괴 도형 데이터 + Command/Undo + 프로젝트 저장**.

이 세 가지를 연결하면 제품이 단순한 3D 화면이 아니라 **아이들이 실제로 쓰는 모델링 앱**으로 작동할 수 있는지 가장 빨리 확인할 수 있다.

### 개발 착수 시 미확정이지만 PoC로 해결할 사항

- `eframe`/`wgpu`의 최종 의존성 버전 및 Windows 10에서의 백엔드 정책.
- Manifold 구현의 선택과 성능.
- Intel HD 500/520의 실제 FPS·메모리 및 최종 지원 범위.
- 키캡·조립 기능에 필요한 추가 형상 엔진 도입 여부(후속 버전 결정).
- 서비스명은 큐빌로(Cubilo)로 확정. 아이콘, 프로젝트 확장자 및 배포 라이선스는 미확정.
